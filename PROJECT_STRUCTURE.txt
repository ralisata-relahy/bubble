Bubble project structure
========================

Architecture
------------
Code is organized by feature. Each feature keeps its data, domain logic,
configuration, presentation, and feature-specific services together. Shared
contracts, physics, UI primitives, and platform services live in core.

Source tree
-----------
lib/
|-- main.dart                         Flutter app bootstrap and composition
|-- core/
|   |-- contracts/                    Shared component/game interfaces
|   |-- physics/                      Reusable collision resolution
|   |-- presentation/widgets/         Shared Flutter UI
|   `-- services/
|       |-- audio/                    Generated sound effects and audio facade
|       `-- haptics_service.dart      Optional vibration integration
`-- features/
    |-- ai_buddy/                     Edutainer models, painters, and widgets
    |-- bubble/
    |   |-- models/                   Bubble motion and visual configuration
    |   `-- presentation/
    |       |-- components/           Flame bubble entities, labels, and knowledge bubble
    |       |-- rendering/            Bubble rendering and text layout
    |       `-- widgets/              Flutter bubble widgets
    |-- curio/
    |   |-- domain/models/           Mood names and pose presets
    |   |-- presentation/widgets/    Character, gauge, timer, and overlay UI
    |   `-- services/                Curio voice playback
    `-- game/
        |-- application/
        |   |-- bindings/             GetX game registration
        |   |-- contracts/            Flame command port
        |   `-- controllers/           Observable game session and commands
        |-- configuration/            Gameplay tuning values
        |-- data/                     Question catalog
        |-- domain/
        |   |-- models/                Question and pop records
        |   |-- game_question_deck.dart Question selection
        |   `-- services/              Ordered, deduplicated pop history
        |-- presentation/
        |   |-- components/           Laser, aiming, confetti, knowledge scatter
        |   |-- overlays/             Flutter win, loss, and skip overlays
        |   |-- systems/              Game-world collision pass
        |   `-- bubble_game.dart      Flame lifecycle and game coordination
        `-- services/                 Question pronunciation playback

test/                                 Unit, widget, and game-logic tests

Dependency direction
--------------------
- `main.dart` composes Flutter and Flame features.
- Game presentation coordinates components and delegates question selection,
  ordered first-hit pop history, collision passes, audio playback, and knowledge
  scatter to focused modules. GetX state lives in the application controller;
  `GameCommandPort` keeps high-level commands explicit across the Flame boundary.
- Curio mood presets are pure domain data; Flutter widgets interpolate and paint
  them, while the Curio audio adapter maps moods to optional voice assets.
- Bubble entities depend on core contracts and services, not on the concrete
  game class.
- Rendering consumes configuration and state; it does not own progression.
