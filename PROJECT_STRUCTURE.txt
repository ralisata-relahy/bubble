Bubble project structure
========================

Architecture
------------
Source code is grouped by feature. Each feature keeps its content/data, domain
models, and presentation code close together. Shared contracts and widgets live
under core so features do not need to own cross-feature infrastructure.

Source tree
-----------
lib/
|-- main.dart                         App bootstrap and top-level composition
|-- core/
|   |-- contracts/
|   |   |-- knowledge_bubble_host.dart Game callbacks required by bubble entities
|   |   `-- laser_target.dart          Contract for laser targets
|   `-- presentation/widgets/
|       `-- space_background.dart     Shared animated background
`-- features/
    |-- ai_buddy/                     Character drawing models and painters
    |-- bubble/
    |   |-- models/                   Bubble configuration and visual style
    |   `-- presentation/
    |       |-- components/           Interactive Flame bubble entities
    |       |-- rendering/            Bubble and cube rendering pipeline
    |       `-- widgets/              Knowledge bubble presentation
    |-- curio/
    |   |-- presentation/widgets/     Character gauge and game overlay
    |   |-- character_backup_widget.dart
    |   `-- character_backup_painter.dart
    `-- game/
        |-- data/game_questions.dart  Static game question catalog
        |-- domain/models/            Typed game question model
        `-- presentation/
            |-- components/           Laser and game-specific Flame entities
            |-- overlays/             Game overlays
            `-- bubble_game.dart      Game lifecycle and round orchestration

Resources and project support
-----------------------------
- `assets/` contains images and sounds declared by `pubspec.yaml`.
- `test/` contains Flutter tests.
- `README.md` and `bubble_customization_guide.md` describe the project and bubble styles.

Dependency direction
--------------------
- `main.dart` composes the Flutter app, background, game, and overlay.
- The game presentation layer reads typed question data and coordinates entities.
- Bubble entities depend on core contracts rather than the concrete game class.
- Rendering code consumes bubble models and does not own game progression.
